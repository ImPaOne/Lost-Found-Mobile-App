================================================================================
BACKEND FILES & ARCHITECTURE EXPLANATION
================================================================================

1. AuthViewModel.kt
   - Role: ViewModel for user registration and sign-up.
   - Why it is used: Manages the sign-up form state, handles input validation, and triggers user creation in AuthRepository.

2. MessagesViewModel.kt
   - Role: ViewModel for the messages inbox.
   - Why it is used: Holds the list of conversations in memory and updates the inbox list in real time.

3. ChatViewModel.kt
   - Role: ViewModel for the active chat room.
   - Why it is used: Manages incoming and outgoing messages, typing indicators, photo uploads, and case resolution.

4. AuthRepository.kt
   - Role: Data repository for user authentication.
   - Why it is used: Calls FirebaseAuth to create accounts and initializes the new user profile in Firebase Realtime Database.

5. MessagesRepository.kt
   - Role: Data repository for inbox conversations.
   - Why it is used: Reads /user_conversations/{uid} and updates last message snippets and unread counters.

6. ChatRepository.kt
   - Role: Data repository for real-time chat messages.
   - Why it is used: Sends chat messages to /chat_conversations/{id}/messages, handles image attachments, and triggers notification records for the recipient.

7. AppNotificationService.kt
   - Role: Sticky Android background service.
   - Why it is used: Runs in the background to monitor incoming chat messages, notification alerts, and admin announcements. Acquires a PowerManager wake lock to show heads-up notifications even when the screen is locked.

8. FloatingOverlayService.kt
   - Role: Android Foreground Service for floating chat bubble.
   - Why it is used: Renders a floating chat head on top of other Android applications using the Android WindowManager.

9. FCMService.kt
   - Role: Notification channel and sound manager.
   - Why it is used: Handles device sound chimes, vibrations, and notification channel configurations.


================================================================================
FIREBASE OPERATIONS USED BY THIS STUDENT
================================================================================

1. Realtime Database Nodes Accessed:
   - /users/{uid}
     * What it is: User profile document.
     * Why it is accessed: Initialized with default 85 Trust XP on sign-up.
   - /users/{uid}/trustScore
     * What it is: User's trust points score.
     * Why it is accessed: Read on Trust & Achievements screen; updated when resolving a lost/found case (+20 points).
   - /users/{uid}/achievements
     * What it is: Badges and milestones unlocked by the user.
     * Why it is accessed: Read on the Trust screen; updated when badges like "Reunited Hero" are awarded.
   - /items
     * What it is: All lost and found items.
     * Why it is accessed: Read on the Map screen to plot GPS coordinates (pins) for lost and found items.
   - /chat_conversations/{conversationId}/messages/{messageId}
     * What it is: The real-time messages list inside a specific chat conversation.
     * Why it is accessed: Read and written to for live two-way messaging between users.
   - /chat_conversations/{conversationId}/typing/{userId}
     * What it is: Real-time typing status flag for a conversation.
     * Why it is accessed: Read and updated to show "...is typing" indicators in chat.
   - /user_conversations/{userId}/{conversationId}
     * What it is: Conversation metadata index for a specific user.
     * Why it is accessed: Keeps track of all conversations a user is part of, with last message preview and unread counts.
   - /notifications/{userId}
     * What it is: User's notification inbox.
     * Why it is accessed: Read to display notifications; written to when a user receives a new chat message or case update.
   - /announcements
     * What it is: System-wide announcements from admins.
     * Why it is accessed: Read in real time by AppNotificationService to broadcast critical alerts to the user.

2. Firebase Authentication Operations:
   - FirebaseAuth.getInstance().createUserWithEmailAndPassword(email, password)
     * Why: Registers new citizen accounts securely with email and password hashing.

3. Real-time Listeners & Stream Operations:
   - ChildEventListener on /chat_conversations/{conversationId}/messages
     * Why: Delivers each new message to the chat screen instantly as soon as it is sent.
   - ChildEventListener on /user_conversations/{uid}
     * Why: Keeps the messages inbox list updated with the latest message snippets in real time.
   - ChildEventListener on /notifications/{uid}
     * Why: Delivers notifications instantly to the notification inbox.
   - ValueEventListener on /chat_conversations/{conversationId}/typing
     * Why: Shows and hides the typing indicator in the chat room.
   - ValueEventListener on /users/{uid}/trustScore and achievements
     * Why: Updates the Trust Score meter and unlocked badge grid in real time.
   - ValueEventListener on /items
     * Why: Loads coordinates for all items where latitude and longitude are set to show pins on the map.

4. Create & Write Operations:
   - Writing to /chat_conversations/{conversationId}/messages/{msgId}
     * Why: Stores chat messages with senderId, recipientId, text, photoUrl (if attached), and timestamp.
   - Writing to /notifications/{recipientUserId}
     * Why: Creates a new notification alert for the recipient when they get a new message or update.
   - Initializing /users/{uid} on sign up
     * Why: Seeds the user profile with full name, email, phone, city, and 85 starting trust points.
   - Writing to /chat_conversations/{conversationId}/typing/{userId}
     * Why: Sets typing status to true or false.

5. Update Operations:
   - Updating /user_conversations/{senderId}/{convId} and /user_conversations/{recipientId}/{convId}
     * Why: Updates last message text, timestamp, and unread count for both users.
   - Updating /users/{uid}/achievements/{badgeId}
     * Why: Unlocks badges such as "Reunited Hero" upon successful case resolution.
   - Updating /users/{uid}/trustScore
     * Why: Awards +20 XP to the finder and +15 XP to the owner when an item is returned.
   - Updating /items/{itemId}/status to "RESOLVED"
     * Why: Closes the item report so it is marked as reunified.
   - Updating /notifications/{uid} read status
     * Why: Marks notifications as read when the user taps "Mark all read" or opens an alert.
