================================================================================
BACKEND FILES & ARCHITECTURE EXPLANATION
================================================================================

1. AuthViewModel.kt
   - Role: ViewModel for authentication and login.
   - Why it is used: Keeps login state, handles communication with AuthRepository, and provides error and success states to the UI without losing state on orientation changes.

2. AuthRepository.kt
   - Role: Repository for Firebase Authentication and user profile operations.
   - Why it is used: Encapsulates all FirebaseAuth API calls (sign in, password reset, sign out) and initial user record verification, separating auth logic from the UI.

3. FirebaseAuth (com.google.firebase.auth.FirebaseAuth)
   - Role: Official Google Firebase Authentication engine.
   - Why it is used: Provides secure token-based user login, password hashing, session tokens, and password reset emails.

4. AppNotificationService.kt
   - Role: Background Android Service for notifications.
   - Why it is used: Starts on splash or login and runs in the background to listen for new chat messages, case resolutions, and announcements even when the app is minimized.

5. FCMService.kt
   - Role: Firebase Cloud Messaging notification builder.
   - Why it is used: Sets up notification channels, plays custom alert chimes, and triggers heads-up alerts on Android devices.


================================================================================
FIREBASE OPERATIONS USED BY THIS STUDENT
================================================================================

1. Realtime Database Nodes Accessed:
   - /users/{uid}
     * What it is: The user's root profile object in the Realtime Database.
     * Why it is accessed: To load profile information (name, avatar, email, stats) and update profile details.
   - /users/{uid}/role
     * What it is: User role ("ADMIN" or "USER").
     * Why it is accessed: Verified during login to check if the user is an authorized administrator.
   - /users/{uid}/isBanned
     * What it is: A boolean flag indicating account ban status.
     * Why it is accessed: Checked during login; if true, the user is blocked from entering the app.
   - /users/{uid}/fcmToken
     * What it is: The device's push notification token.
     * Why it is accessed: Updated on login so cloud notifications can be routed to this specific phone.
   - /users/{uid}/fullName, phoneNumber, city, avatarUrl
     * What it is: Profile data fields.
     * Why it is accessed: Updated when the user edits their profile in the Edit Profile modal.

2. Firebase Authentication Operations:
   - FirebaseAuth.getInstance().signInWithEmailAndPassword(email, password)
     * Why: Verifies user credentials securely against Firebase Auth servers.
   - FirebaseAuth.getInstance().sendPasswordResetEmail(email)
     * Why: Sends an official password reset link to the user's email if they forgot their password.
   - FirebaseAuth.getInstance().signOut()
     * Why: Terminates the active session and revokes authentication tokens when the user signs out.
   - FirebaseAuth.getInstance().currentUser
     * Why: Checked on the Splash Screen to determine whether an active session already exists.

3. Read & Stream Operations:
   - ValueEventListener on /users/{currentUid}
     * Why: Streams live profile updates (items reported, items reunited, trust score) directly to the Profile screen.
   - Checking /users/{uid}/isBanned
     * Why: Ensures suspended accounts cannot sign in.

4. Update Operations:
   - Updating /users/{currentUid}/fullName, phoneNumber, city, avatarUrl
     * Why: Saves changes made in the Edit Profile modal.
   - Updating /users/{uid}/fcmToken
     * Why: Keeps the device notification token fresh whenever a user logs in.

5. Storage & Upload Operations:
   - Compressing user avatar image to 512x512 resolution.
   - Uploading avatar to cloud storage and storing the generated URL in /users/{currentUid}/avatarUrl.
